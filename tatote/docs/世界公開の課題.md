# タトる サーバー構成と世界公開に向けた課題

更新日：2026-08-05（Build 10）

## 現在の構成

- アプリサーバー：Cloudflare Workers
- データベース：Apple CloudKit公開DB
- 外部公開：Cloudflare Workers Route
- 公開URL：`api-tatoe.chikumo.jp`
- 実体：Cloudflareのエッジ実行環境。Mac miniは本番通信経路に含めない
- 通知：WorkerからApple Push Notification service（APNs）へ直接送信
- APNs環境：TestFlight用Production
- iPhone通知Topic：`jp.chikumo.tatoe`
- Apple Watch通知Topic：`jp.chikumo.tatoe.watchkitapp`

`api-tatoe.chikumo.jp/*`はCloudflare Workerへ接続する。認証・友達・端末・回数制限はCloudKitへ保存し、通知はCloudKitサブスクリプションを経由せずWorkerからAPNsへ送る。

## 現状の適用範囲

Mac miniの電源状態に依存しないTestFlightベータとして使用できる。世界公開の段階的拡大は、負荷試験と実機通知測定の結果に従う。

## 世界公開時の課題

- CloudKitの同一利用者レコードへの高並行更新では競合測定が必要
- 12時台の集中負荷試験が未実施
- 2台の実機で、ロック中・低電力モードを含む20回の着信／振動測定が未実施
- CloudflareとCloudKitの利用量・エラー率アラートが未設定
- APNsの受付成功は端末到達を保証しないため、実機測定を継続する必要がある

## 公開前に必要な移行

1. 12時相当の同時アクセス負荷試験を実施する
2. Cloudflare AnalyticsとCloudKitエラーの監視を設定する
3. CloudKitデータの定期書き出しと復旧手順を作る
4. 同一利用者レコードの競合率を測定し、必要時だけDurable Objects等の直列化層を追加する
5. TestFlight実機通知試験を実施する

## 結論

Mac mini非依存化は完了した。世界公開ベータは開始できるが、利用者を段階的に増やし、負荷・競合・実機到達時間を測定してから公開枠を拡大する。
