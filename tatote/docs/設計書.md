# タトる — 振動コミュニケーションアプリ設計書

生成日：2026-08-03  
Bundle ID：`jp.chikumo.tatoe`

## プロダクト核（Build 5で固定）

- 分類：利用者が文字、音声、画像、位置情報を入力・選択せず、承認済みの相手へ振動を伴う通知を1件送る振動コミュニケーション
- 通信単位：自由入力本文を持たない1回の合図。配送と表示に必要な送信者ID・送信者表示名・固定通知文だけを使用し、メール、チャット、通話、ポケベル、モールス信号の送受信機能は持たない
- 利用場面：同じ勤務場所にいる固定メンバーが、ランチ、休憩、朝のコーヒー購入などの反復ルーティンを開始する直前
- 最優先順位：①通知API要求開始までの操作工数、②タップから通知受信までの時間、③それ以外の機能。①または②を増加させる機能は無料版へ追加しない
- 無料版の送信導線：Watchは「文字盤のComplicationをタップ→相手名をタップ」の2工数。iPhoneは「ロック解除または本人認証→ウィジェット内の相手名をタップ」の2工数以下
- 禁止する送信途中操作：本文入力、合図選択、送信確認、送信先検索、7人以内の送信先表示に必要なスクロール、アプリ内中間画面への遷移
- 受信結果：受信者が登録したiPhoneとApple Watchの各APNs tokenへ同一要求を並行投入し、両端末で表示通知とシステム振動を要求する。片方の受信完了をもう片方の送信開始条件にしない

### 操作工数の測定規則

- 1工数：利用者によるタップ、スワイプ、Digital Crown操作、Face ID・Touch ID・パスコードによる本人認証のいずれか1回
- Watchの測定起点：文字盤を表示した状態。測定終点：相手名タップにより通知API要求が開始した時点
- iPhoneの測定起点：画面点灯済みのロック状態。測定終点：ウィジェットの相手名タップによりAppIntentが通知API要求を開始した時点
- iPhoneが解除済みの場合：ホーム画面ウィジェットの相手名タップ1工数で通知API要求を開始する
- 合格条件：友達が1〜3人の全状態で、各名前が同時表示され、Watchは2工数、ロック中のiPhoneは2工数以下、解除済みiPhoneは1工数で送信要求を開始する

### 通知速度の測定規則

- `T0`：Watchの名前ボタンまたはiPhoneウィジェットの名前ボタンがAppIntent/APIクライアントへ入力された時刻
- `T1`：通知サーバーが要求を最初に受信した時刻
- `T2-phone` / `T2-watch`：通知サーバーが受信者のiPhone / Watch宛てAPNs要求を開始した時刻
- `T3-phone` / `T3-watch`：実機が通知を受信した時刻。TestFlight実機試験では画面収録または端末ログで計測する
- 自動試験の合格条件：`T1-T0`は95パーセンタイル1200ms以下、`|T2-phone-T2-watch|`は50ms以下、両APNs要求は`T1`から300ms以内に開始する
- TestFlight実機試験の合格条件：同一Wi-Fi、集中モードなし、通知許可あり、iPhoneとWatchの通知時の触覚が有効、受信端末ロック、Apple Watch装着かつロック解除の条件で20回測定し、両端末の通知受信率100%、両端末の振動確認率100%、`max(T3-phone,T3-watch)-T0`の95パーセンタイル2秒以下、`|T3-phone-T3-watch|`の95パーセンタイル1秒以下
- 外部前提の扱い：APNsまたは通信回線の障害時は実機到達時間の合格判定から除外せず、前提破れとして別記録する。アプリは到達完了を表示せず、APNs受理、確定失敗、結果不明だけを表示する

## UI / 画面構成

### 操作系（確定済み）

- メイン操作：Watch一覧またはiPhoneウィジェット内の同僚名ボタンのタップ
- Digital Crown：同僚名一覧の縦スクロール
- iPhoneウィジェット：`Button(intent:)`からAppIntentをバックグラウンド実行し、アプリを開かず通知API要求を開始する
- 受信操作：操作なし。受信時はiOS/watchOSの表示通知とシステム振動を使用する

### ナビゲーション構造（確定済み）

- Watch主要画面数：1画面（名前一覧）
- iPhone主要画面数：3画面（友達・招待・設定）。Liquid GlassのコンパクトなTabViewで切り替える
- iPhoneウィジェット：ホーム画面1種、ロック画面1種。アプリ主要画面数には含めない
- Watchの名前一覧画面は縦スクロールに対応する
- 友達追加はiPhone上で招待コードを入力して行う

### ビジュアル方針（確定済み）

- 視覚表現：大きな文字の名前ボタン
- 配色：黒を基調とする標準コンテンツ背景、白文字、青紫の補助光、青緑の受付色
- 送信側Haptic：Watch、iPhoneともなし
- Complication：必要。文字盤から名前一覧画面を起動する
- iPhoneウィジェット：必要。登録済みの友達を最大3人まで表示し、名前ボタンから直接送信する

### Liquid Glassデザインシステム

- 適用範囲：操作要素とナビゲーションだけにLiquid Glassを使用する。コンテンツ背景へLiquid Glassを敷かない
- Watch背景：黒の標準コンテンツ層。上部左と下部右に低彩度の青紫・青緑の光を置き、名前ボタン越しに限定して見せる
- 名前ボタン：`regular`相当のLiquid Glass、全幅、高さ57pt以上、角丸23pt、縦間隔9pt
- フォント：AppleシステムフォントSan Franciscoを使用する。iPhoneはSwiftUIの`.system`によるSF Pro、Apple Watchは同じ`.system`指定でwatchOSが選ぶWatch向けSan Francisco字形を使用する。フォントファイルを同梱しない
- 名前文字：中央揃え、白、20pt、Medium（`.font(.system(size: 20, weight: .medium, design: .default))`）。Dynamic Type時は1行を維持して縮小
- iPhone見出し：Large Title相当（`.font(.largeTitle.weight(.medium))`）
- iPhone本文：Body相当（`.font(.body)`）、補助情報はFootnote相当（`.font(.footnote)`）
- 数字：時刻・残り時間だけ`.monospacedDigit()`を使用し、名前と本文には使用しない
- 通常：白20%相当の半透明面、白22%相当の輪郭、上辺に細い光
- 押下：160msで96%へ縮小。離した時に元へ戻す
- 受付：青緑の透過色＋チェック記号を0.8秒表示
- 確定失敗：赤の透過色＋×記号を2秒表示
- 結果不明：グレーの透過色＋…記号を2秒表示
- Always On：光量と彩度を下げ、文字・記号の形状だけで状態を判別可能にする
- 透明度を下げる設定：不透明度の高い標準背景へ切り替え、輪郭を強める
- 視差効果を減らす設定：押下の縮小・状態遷移を即時切替へ変更する
- 実装原則：標準SwiftUIコンポーネントを優先し、カスタム`glassEffect`は名前ボタンと主要ナビゲーションだけに限定する

### アプリアイコン

- 構成：黒の基層、青紫と青緑の2枚の円形層、中央に白い1本のタップ波形
- 文字：使用しない
- Icon Composer：iPhoneとApple Watchで共通の多層アイコンを作成し、光源変化とDark/Tinted表示を確認する

### 占有率・情報密度（確定済み）

- 画面占有方針：セーフエリア内で横幅いっぱいに名前ボタンを配置
- 情報密度：無料版の3人全員を、Watch一覧とiPhoneホーム画面ウィジェットで同時表示する。ロック画面は1ウィジェットにつき設定済みの1人を表示し、配置可能数はiOSのロック画面レイアウトに従う
- スクロール設計：Watch一覧は指の縦スワイプとDigital Crownの両方に対応する。3人以内ではスクロール操作をせず全員を選択できる。iPhoneウィジェット内はスクロールしない
- 機種別対応：小型Watchを含め、画面幅に応じて文字サイズとボタン寸法を自動調整

### Complication仕様

- 種別：WidgetKitの`accessoryCircular`
- 表示内容：タトるのアイコンと送信可能な友達数。個人名は表示しない
- タップ動作：Watchの名前一覧画面を開く
- 更新トリガー：友達一覧の同期完了時

### iPhoneインタラクティブウィジェット仕様

- 実装：WidgetKitのウィジェット拡張とAppIntentを使用する。名前タップでiPhoneアプリを前景起動せず、ウィジェット拡張から通知APIへ要求する
- ホーム画面：`systemMedium`に友達を並び順どおり最大3人、縦1列で表示する。各名前の全領域をタップ対象とする
- ロック画面：1人を固定した`accessoryRectangular`を用意する。友達の選択はウィジェット追加・編集時だけ行い、送信時には行わない。配置可能数はiOSのロック画面レイアウトに従う
- 認証：ロック中はiOSが要求するFace ID、Touch IDまたはパスコード認証後にAppIntentを実行する。認証を省略する実装は行わない
- 友達データ：App Groupに保存した最大3人のID・表示名・並び順を参照する。友達追加・承認・解除・並び順変更時にiPhoneアプリが完全な一覧で上書きし、WidgetKitのTimelineを再読み込みする
- 送信資格：iPhoneアプリがApp Groupへ保存した24時間有効のアクセストークンだけを使用する。refresh token、Apple identity token、APNs認証鍵はウィジェットへ保存しない
- 期限切れ：アクセストークンが失効または残存時間0の場合は通知APIへ要求せず、対象名を赤と×記号で表示し、iPhoneアプリを開いて更新する導線を出す
- 状態：送信受付は青緑とチェック、確定失敗は赤と×、2秒で結果未確定はグレーと…で区別する。APNs受理を端末到達または振動完了として表示しない
- 操作禁止：送信時の確認画面、本文入力、合図選択、アプリ起動、ウィジェット内スクロールを行わない

### アクセシビリティ

- VoiceOver：各ボタンを「〈名前〉さんへ合図を送る」と読み上げる
- Dynamic Type：利用可能な横幅と文字サイズ設定に応じて縮小率を調整する
- Haptic：受信側の表示通知に付随するiOS/watchOS標準のシステム振動を使用する。任意の回数・間隔は保証しない
- 状態表現：受付はチェック、失敗は×、結果不明は…を併記し、色だけで状態を伝えない
- `accessibilityReduceTransparency`：有効時はLiquid Glassを高不透明度の標準面へ置換する
- `accessibilityReduceMotion`：有効時は96%縮小アニメーションを行わない

## データ / 永続化

### データモデル

| エンティティ | 主なフィールド | 保存先 |
|---|---|---|
| User | 内部ID、Apple認証ID、表示名 | CloudKit公開DB |
| Device | User ID、APNs device token、端末種別、pausedUntil、更新日時 | CloudKit公開DB |
| Friendship | 申請者ID、承認者ID、承認状態、作成日時、保留期限 | CloudKit公開DB。保留は24時間TTL |
| Invitation | 発行者ID、コードハッシュ、有効期限、使用日時 | CloudKit公開DB・10分TTL |
| LocalFriend | 友達ID、表示名、並び順 | iPhoneローカル＋Watch同期キャッシュ |
| WidgetSession | 24時間アクセストークン、有効期限、最終同期日時 | iPhoneとiPhoneウィジェットだけが参照するApp Group |
| UserState | Apple利用者ID、表示名、友達、承認待ち、端末token、一時停止、当日残数、10秒窓 | CloudKit公開DB（Workerのサーバー間鍵だけで更新） |
| RateLimit | 送信者ID、受信者ID、10秒窓の開始時刻、追加タップ数 | CloudKit UserState内 |
| RequestDedup | 要求ID、直近処理時刻、追加タップ数 | CloudKit UserState内 |

- 利用者向け送信履歴：保存しない
- 診断イベント：要求ID、結果コード、処理時間、再試行回数を7日間だけ保存する。表示名と通知本文は含めない
- 認証情報：iPhone Keychainへ保存
- Watch認証情報：iPhoneが取得した24時間有効のアプリ用アクセストークンをWatchConnectivityでWatch Keychainへ同期する。有効期限が6時間未満になった時点でiPhoneが更新して再同期する。APNs認証鍵とSign in with Appleの資格情報は同期しない
- iPhoneウィジェット認証情報：24時間アクセストークンと有効期限だけをApp Groupへ同期する。refresh token、Apple identity token、APNs認証鍵は同期しない。ログアウト・退会時に同時削除する
- Watchキャッシュ：友達一覧と同期日時のみを保存
- iPhoneウィジェットキャッシュ：友達最大3人のID・表示名・並び順、アクセストークン、有効期限、直近の送信表示状態だけを保存する。利用者向け送信履歴として使用しない
- 一時停止：受信者が設定した`pausedUntil`をDeviceへ保存し、その時刻まではサーバーがAPNsへ投入しない

### 外部連携

- 本人確認：Sign in with Apple
- 送信経路：Watch名前タップまたはiPhoneアプリ/ウィジェット名前タップ → Cloudflare Worker。WatchとiPhoneウィジェットはiPhoneアプリの前景起動を経由しない
- 保存経路：Cloudflare Worker → CloudKit公開DB。アプリ端末へCloudKitサーバー間秘密鍵を配布せず、Workerだけが署名して保存・取得する
- 受信経路：Cloudflare Worker → APNsへ受信者のiPhone tokenとWatch tokenを並行投入 → 受信側iPhoneとApple Watch
- 同時通知：iPhone宛てAPNs要求とWatch宛てAPNs要求を同じ処理内で開始し、一方のAPNs応答または端末受信を待ってから他方を開始しない
- 速度方針：CloudKitのレコード変更通知を通知経路に使用せず、WorkerからAPNsへ直接送信する。CloudKitは認証・友達・端末・制限値の保存にだけ使用する
- 通知形式：ユーザー操作に対応する表示通知。バックグラウンド通知のみには依存しない
- 通知音：iPhoneアプリとWatchアプリに同梱した無音の通知音を指定し、通知に付随するiOS/watchOS標準のシステム振動だけを要求する。可聴音が出ないことと両端末で振動が発生することはTestFlight実機で確認する
- 連打制御：同一送信者・受信者間の最初のタップを合図1件として確定し、その時点で有効なiPhone/Watch tokenへ各1回だけAPNs要求を投入する。10秒以内の追加タップは最大4回まで送信側の回数表示を更新し、どのtokenにもAPNs要求を追加しない。6回目以降は無視する
- 1日上限：送信者の端末が通知API要求へ付ける現在のタイムゾーン差を用い、送信者の現地時刻0:00で当日回数を0、残数を100へ戻す。iPhone・Watchのローカル表示も同じ現地日付の変更で100へ戻す
- 残数同期：通知API応答だけを確定値としてiPhone・Watch・ウィジェットへ保存する。iPhoneからWatchへ友達一覧と共に残数を同期し、Watchから送信した場合はWatch自身が応答値を即時反映する
- 並行要求：各タップに単調増加する操作番号を付ける。名前ボタンの状態を更新できるのは当該友達に対する最新操作番号の応答だけとする
- 通信時間配分：初回API要求はタップから2秒まで継続し、600msで結果未確定なら同一要求IDの第2要求を並行開始する。第2要求もタップから合計2秒の期限内だけ待つ
- サーバー投入期限：サーバーが同一要求IDを最初に受信してから1200msをAPNs投入期限とする。期限後はAPNsへ送らず`expired`を返す
- 結果不明：WatchまたはiPhoneウィジェットがタップから2秒で最終結果を得られない場合、失敗と断定せず名前ボタンを2秒間グレーにする。確定失敗だけを2秒間赤色にする
- 通知文面：タイトル「タトる」、本文「〈送信者の表示名〉さんが外へ行きます」
- APNs再送：自動再送しない。応答不明時の重複通知を防ぐため、同一要求をAPNsへ再投入しない
- 無効token：APNsの`410 Unregistered`受信時に当該tokenだけを無効化する。受信側iPhoneまたはWatchの次回起動時に該当端末のtokenを再登録する
- 同期：iPhoneからWatchへWatchConnectivityのapplication context、即時message、最新1件のuser info転送を併用して友達一覧・短命トークン・残数を送る。Watchは適用した同期版番号をiPhoneへ返し、未確認の最新状態は到達可能になった時に再送する
- 再同期：Watchアプリ起動時にiPhoneへ完全同期を要求する。iPhoneは現在の友達一覧・短命トークン・残数を再送する。各同期に単調増加する版番号を付け、Watchは適用済み版番号より古いデータで上書きしない

### iPhone連携

- iPhoneで友達に表示する名前を1〜40文字で入力し、Appleアカウント認証、招待コードの発行・入力、友達承認、友達解除を行う。Appleから氏名・メールの共有は要求しない
- iPhoneアプリの友達画面でも名前タップから送信できる。ホーム画面・ロック画面ウィジェットはアプリを開かず同じ通知APIを呼ぶ
- Apple認証要求ごとに乱数nonceを作成し、SHA-256値をAppleへ、元の値を通知サーバーへ送り、identity tokenの署名・発行者・対象・期限・nonceを全て検証する
- 招待コード：英数字8文字、10分間有効、1回使用で失効。サーバーにはハッシュだけを保存する
- 友達成立：コード入力後、コード発行者がiPhone上で承認した時点で成立する。承認前はWatch一覧とiPhoneウィジェットへ表示せず、通知も送れない
- 承認保留：コード入力から24時間。承認、拒否または期限切れで保留状態を終了し、拒否・期限切れでは保留レコードを削除する。削除後は新しいコードで再申請できる
- iPhoneで短命のアプリ用アクセストークンをWatch Keychainへ同期する
- iPhoneで短命のアプリ用アクセストークンと友達最大3人の完全な一覧をApp Groupへ同期し、ウィジェットTimelineを再読み込みする
- トークン更新トリガー：iPhoneアプリの前景起動時、OSが許可したバックグラウンド更新時、Watchから更新要求を受けてiPhoneが到達可能な時。残存時間6時間未満なら24時間トークンを再発行する
- 更新結果のWatch到達は即時保証しない。Watchは受信済みトークンの有効期限を判定し、失効中は送信しない
- WatchとiPhoneウィジェットでは、それぞれ同期済みの友達一覧から送信する
- 設定画面に「今日は停止」を置き、選択時から当日23:59まで受信通知を停止する。翌日0:00に自動解除する

## 鳴分岐

### 成立判定

本設計では専用サーバーの認証・友達・レート制限処理を中央に含め、APNsと受信端末を現場とする。WatchまたはiPhoneの名前タップは思の素材としてサーバーへ渡す。サーバーが次の全条件を判定できた場合に鳴が成立する。

1. 送信者の認証が有効
2. 対象が承認済みの友達
3. 対象のiPhoneまたはWatchのAPNs device tokenが1件以上登録済み
4. 同じ送信者・受信者間で直近10秒に合図のAPNs投入がない。投入済みの場合は追加タップ数だけを更新し、どのtokenにも再投入しない
5. 送信要求IDを一意に生成済み

### 反復上限

- 中央処理の再判定：1回
- Watch/iPhoneから通知APIまでの通信再試行：初回接続を全体期限2秒まで維持し、600msで結果未確定なら同一要求IDを1回だけ並行再送する。サーバーは同一要求IDを1回だけ処理する
- サーバーからAPNsへの自動再試行：0回
- 1回の送信操作の判定期限：2秒

### 三経路

- 成立：サーバーが確定済み送信要求をAPNsへ示す
- 思戻り：Watch/iPhoneから通知APIまでの通信失敗で結果を得られず、同一要求IDの再送素材がある場合に1回だけサーバー判定へ戻す
- 打切り：条件不足、反復上限、サーバー投入期限到達の場合は送信せず、対象の名前ボタンを2秒間赤色にする
- 結果不明：送信面の2秒期限までに最終結果を得られない場合は、対象の名前ボタンを2秒間グレーにする。APNs到達または失敗を断定しない
- 外部依存：APNsの到達時刻、到達順、端末側の通知表示、振動回数は中央で確定しない。送信サーバーがAPNsから要求受理応答を得た状態までを成立判定とする

### 差分記録

- 記録項目：要求ID、送信者削除キー、受信者削除キー、結果コード、処理時間、再試行回数、打切り理由、作成日時
- 重複送信防止用に要求ID、送受信者内部ID、処理状態を最大24時間保存する。表示名と通知本文は保存せず、利用者が閲覧する送信履歴は作らない
- 保存期間：重複送信防止情報は24時間、診断イベントは7日で自動削除する。退会時は当該利用者に帰属する未削除情報を削除する

## 示式十項

### 1 目的

WatchまたはiPhoneウィジェットの名前ボタンを押すと、確認画面・本文入力・送信先スクロールを経ず、承認済みの同僚が登録したiPhoneとWatchへ反復ルーティン開始の表示通知とシステム振動の要求が並行して実体化する。

### 2 幅

- 対象端末：watchOS 26以上、iOS 26以上
- 対象者：Appleアカウントで認証済みの利用者
- 対象関係：招待コードを通じて承認済みの友達
- 入力：1回以上の名前ボタンタップ
- 操作工数：Watchは文字盤から2工数、ロック中のiPhoneは本人認証を含め2工数以下、解除済みiPhoneは1工数
- 画面内送信先：無料版の友達最大3人。送信時の検索・スクロール・確認・本文入力なし
- 送信上限：同一送信者・受信者間で10秒間に合図1件。合図1件につき各device tokenへAPNs要求1件。追加タップ表示は合計5回まで
- 外部前提：インターネット接続、APNs稼働、通知許可、iPhoneとWatchの通知時の触覚が有効、受信端末の到達可能性、ロック画面ウィジェット実行時の本人認証成功、ウィジェット用アクセストークンの有効性
- 通信またはAPNs前提破れの帰結：通信復帰後の自動大量再送は行わず、確定失敗は赤、2秒で結果未確定はグレーとして当該要求を終了する。次の利用者タップを新しい周回とする
- 本人認証前提破れの帰結：AppIntentを実行せず、OSのロック状態を維持する。通知要求を保存または予約しない
- ウィジェット用トークン前提破れの帰結：通知APIへ要求せず赤と×を表示し、iPhoneアプリを開いて更新する導線を出す。自動送信は行わない
- iPhoneまたはWatchの片方だけtokenが有効な場合：有効な端末へ送信し、無効なtokenを無効化する。両端末同時通知の実機試験は不合格として差分へ記録する
- APNsが要求を受理しない場合：自動再送せず終了する。利用者が次にタップした場合は新しい要求IDによる別の周回とする
- APNs投入期限：サーバーの初回要求受信から1200ms。期限後はAPNsへ投入せず`expired`で終了する
- Watch認証トークン失効：iPhoneが到達可能なら更新同期を試みる。到達不能なら送信を打ち切り、「iPhoneでタトるを開いてください」を表示する

### 3 許

定め手：アプリ所有者。以下を全必須とする。

1. 未承認の相手へ通知要求を送らない
2. サーバー側で同一送信者・受信者間の合図を10秒間に1件とし、その合図を各device tokenへ1回だけ投入する。追加タップはどのtokenにも送らず回数表示だけを最大5まで更新する
3. APNsが要求を受理した場合、送信側を通常表示へ戻す。ただし端末到達または振動完了を示す表示は行わない
4. 確定失敗は対象ボタンを2秒間赤色、送信面の2秒期限で結果未確定の場合は2秒間グレーにして通常色へ戻す
5. 退会処理でアカウント、友達関係、端末情報を削除する
6. 利用者向け送信履歴を保存しない。重複送信防止情報は表示名と本文を含めず24時間、診断イベントは表示名と本文を含めず7日で削除する
7. 無料版の友達1〜7人で、Watchは2工数、ロック中のiPhoneは2工数以下、解除済みiPhoneは1工数で通知API要求を開始する
8. 送信時に本文入力、合図選択、送信確認、送信先検索、3人以内の送信先表示に必要なスクロールを要求しない
9. iPhone・Watch宛てAPNs要求を並行開始し、開始時刻差を50ms以下にする。TestFlight実機試験では両端末の通知受信率・振動確認率を各100%とし、20回の95パーセンタイルで受信時刻差1秒以下にする

- 設計判定：アプリ所有者
- 通信判定：自動テストおよびサーバーメトリクス
- 実機判定：TestFlight参加者2人以上
- 操作工数判定：アプリ所有者またはTestFlight参加者が、操作画面収録を1操作単位で計数する

### 8 適応

- 開発者別のファイル配置、命名補助、作業順序のみを差し替え可能とする
- Bundle ID、許、通知上限、保存対象、画面動作は差し替えない

### 9 差分

- 記録先：本設計書末尾の「検証差分」
- 形式：日付、ビルド番号、端末、操作、期待値、実測値、帰属先
- 帰属先：Watch UI、iPhone UI、iPhoneウィジェット、AppIntent、同期、認証、友達API、通知API、APNs並行投入、iPhone受信、Watch受信、データ削除
- 次周回がない場合：再利用可能な差分を事例庫へ移す

### 10 継

- 同じ差分が複数ビルドで再現した場合のみ、次周回の許または工程の候補にする
- 設計変更は次周回の鳴で確定し、更新日を記す
- ビルドnの検証差分を記録後、ビルドn+1の認へ遷移する

### 構成式

- 送信衡（認思鳴示応）＝Watchの起動・名前タップまたはiPhoneウィジェットの名前タップ→サーバー照合→要求確定→iPhone/Watch宛てAPNs並行指向→要求結果の送信面実体化
- 受信衡（認思鳴示応）＝iPhone/WatchのAPNs通知受信→各端末状態照合→表示確定→通知UI・振動への指向→表示通知・振動の実体化
- 縁＝送信衡+ ∿ 受信衡-（同一要求ID、双方成立時のみ）
- 家＝送信側または受信側の（思鳴 ∿ 示応）が安定並列して完了する単位
- 継ₙ→認ₙ₊₁＝各衡の応成立→各側の次受付

## 受け入れ試験

1. 2つのAppleアカウントが招待コードで友達関係を成立できる
2. iPhoneで追加・解除した友達の最新完全一覧がWatchへ自動反映される。同期の即時性は合格条件にしない
3. Watchに名前ボタンが縦1列、画面内3人、幅いっぱいで同時表示され、3人以内では指またはDigital Crownによるスクロールをせず全員を選択できる
4. Watchの文字盤を起点に、Complicationタップと相手名タップの2工数で通知API要求が開始する。本文入力・確認・検索・合図選択・中間画面遷移を行わない
5. iPhoneホーム画面ウィジェットに友達最大3人が同時表示され、解除済みホーム画面を起点に相手名タップ1工数で、アプリを開かずAppIntentから通知API要求が開始する
6. iPhoneロック画面に友達を1人固定したウィジェットをiOSが許す個数配置でき、ロック状態を起点に本人認証と相手名タップの2工数以下で、アプリを開かずAppIntentから通知API要求が開始する
7. Watch、iPhoneアプリ、iPhoneウィジェットの名前タップで、認証済みの友達にだけ通知要求が送られる
8. 受信iPhoneとWatchの両方でタイトル「タトる」、本文「〈送信者の表示名〉さんが外へ行きます」が表示され、iOS/watchOS標準のシステム振動が各端末で少なくとも1回発生し、可聴音は発生しない
9. 制御条件下の20回で、受信iPhoneとWatchの通知受信率・振動確認率が各100%、`max(T3-phone,T3-watch)-T0`の95パーセンタイルが2秒以下、端末間受信時刻差の95パーセンタイルが1秒以下になる
10. サーバーがiPhone/Watch宛てAPNs要求を並行開始し、`T1`から各要求開始まで300ms以下、開始時刻差50ms以下になる。一方の応答を他方の開始条件にしない
11. 受信者がiPhoneしか登録していない場合も、iPhoneから送信と受信ができ、表示通知とシステム振動が発生する
12. 10秒間の最初のタップだけを合図1件として各有効device tokenへ1回ずつAPNs投入し、2〜5回目は送信側の回数表示だけを更新し、6回目以降は表示回数も更新しない
13. 未承認、認証切れ、サーバー投入期限切れ、APNs確定失敗で対象ボタンが2秒間赤色と×記号になる。送信面の2秒期限で結果未確定の場合は2秒間グレーと…記号になる
14. 送信側のWatchとiPhoneは名前タップ時に振動しない
15. Complicationから名前一覧を直接開ける
16. 退会後、利用者に紐づくアカウント、友達関係、端末情報、App GroupのWidgetSession・友達キャッシュ、未削除の診断イベントを取得できない
17. 利用者向け送信履歴が保存されず、診断イベントが7日後に削除される
18. iPhoneが到達不能でも、Watch Keychainの有効な短命トークンで送信要求が成立する
19. iPhone前景起動、許可されたバックグラウンド更新、到達可能なWatchからの更新要求の各トリガーで、残存時間6時間未満なら24時間トークンを更新してWatchとiPhoneウィジェットへ再同期する
20. Watchのトークン失効中にiPhoneへ到達できない場合、APNs要求を行わず「iPhoneでタトるを開いてください」と表示する
21. iPhoneウィジェットのトークン失効中はAPNs要求を行わず、対象名を2秒間赤色と×記号で表示し、iPhoneアプリを開いて更新する導線を出す
22. iPhoneウィジェットはrefresh token、Apple identity token、APNs認証鍵を保存・送信しない
23. 同一要求IDをWatchまたはiPhoneから再送しても、サーバー処理と各device tokenへのAPNs送信は各1回だけである
24. 5回の応答順が入れ替わっても、最新操作番号の結果だけが名前ボタンの色を更新する
25. 10秒以内の追加タップでは名前ボタンに「×2」〜「×5」を表示し、APNs通知を追加しない
26. APNsの`410 Unregistered`後は該当tokenだけが無効化され、受信側iPhoneまたはWatchの次回起動で該当端末のtokenが再登録される
27. 招待コードは10分経過または1回使用で失効し、コード発行者の承認前には通知できない
28. 診断イベントは送受信者の削除キーで検索でき、退会時または作成7日後に削除される
29. 初回API要求は全体期限2秒まで継続し、600ms時点で最終結果がなければ同一要求IDの第2要求を並行開始し、両要求をタップから合計2秒で打ち切る
30. サーバー初回受信から1200msを超えた要求はAPNsへ投入されず`expired`になる
31. WatchまたはiPhoneが2秒で最終結果を得られない場合は2秒間グレーになり、確定失敗の赤色と区別される
32. 承認保留は24時間で削除され、拒否・期限切れ後は新しいコードで再申請できる
33. 無料版では4人目の友達追加を拒否し、有料機能の購入を要求せず「無料版は3人まで」と表示する
34. 「今日は停止」を選ぶと当日23:59までサーバーが当該DeviceへのAPNs投入を停止し、翌日0:00に解除する
35. Complicationに個人名を出さず、送信可能な友達数を表示する
36. 有料化の開始条件6項目を満たさないビルドではサブスクリプションUIと購入処理を公開しない
