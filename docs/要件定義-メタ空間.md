## 森林木（設計学）での位置

- **森（家）**＝畜物語そのもの。共有の臓器のうち、本作が繋ぐのは 🔄強制更新／音の番人／公式 `/chikumo.svg`／1ファイル自己完結。世界ランキング祭壇は繋がない（ゲームでないため。範囲を見よ）。
- **林（縁）**＝**品種の林**（標準学 巻二「こっこちゃんは品種である」）。これまでこっこは全作で公式SVGの板（ビルボード）として立っていた。本作はその品種を**立体で**定める最初の木であり、ここで作る「公式SVGから立体を起こす手順」は、他の3D作（`mori`・`splat3d`・`gp` 等の板のこっこ）がのちに継げる共有の臓器の候補になる。
- **木（衡）**＝本作。部屋の台座に立つ立体のこっこを、回して眺め、つついて応えさせ、一日（60秒）が暮れて眠るまでを見届ける部屋。

## 鳴分岐（工程0思→1鳴で判定・ラベルにしない）

**① 成立判定（実行者によらず判定可能な一文）**
> 「`/meta/` を開いて『さわってみる』を押すと、公式 `/chikumo.svg` から実行時に生成した立体のこっこちゃんが部屋の台座に立ち、正面から見た輪郭が公式SVGと一致し（シルエットの IoU ≥ 0.95 を実測）、ドラッグで回すと横と背面に厚みのある体（背面に顔は無い）が見え、つつくとその場所がへこんで弾み、部位ごとに違う音が鳴り、二本の指が同時に触れると『ぎゅっ』の反応が出て、開始から60秒で日が暮れてこっこが眠り、音が止んだ静寂のあとに『おやすみ』で必ず終わり、WebGL が使えない端末では公式SVGの2D表示に落ちて動き、pageerror がゼロである単一HTMLが動く」──これが言えたら成立。

**② 反復の上限（幅の内に記す）**
> 3D化の方式は**最大3案・当日中**で打ち切る。
> - 案1＝球・楕円体を組み合わせてこっこを造形し直す → **品種の描き変え**（標準学 巻二・畜学 補「こっこの顔は借り物を描くな、必ず公式SVGを呼べ」）で棄却。
> - 案2＝公式SVGを板として奥行き方向へ押し出す → 横から見ると厚い板で「ふくらみ」が出ず、背面に顔が透ける。棄却。
> - 案3＝公式SVGのシルエットの距離場から**内接球の和**でふくらませ、正面に公式SVGをそのまま投影、背面には顔の部位を外した公式SVGを投影する → 採用。
>
> 部屋の「終わり」は**最大2案**。案A＝終わりなし（島ぐらしと同じ実験室扱い）→ 弐（底なしの禁）に背くため棄却。案B＝60秒で一日が過ぎ、こっこが眠って静寂で終わる → 採用。

**③ 通った経路（差分として残す）**
> 経路＝**思戻り1回 → 成立**。
> 案3の初稿は「輪郭線ごと焼いたテクスチャ」で膨らませる形だった。これを中央で詰めると、シルエットの縁（距離0〜線幅）は膨らみの急な壁に当たるため、**横から見ると輪郭線の黒が胴の周りに太い帯として巻きつく**と分かった（新規素材＝中央で確定可能）。素材を思へ加え、**シルエットを輪郭線の幅だけ内側へ削ってから膨らませ、輪郭線は外殻（法線方向へ押し出した裏面）で描き戻す**形へ寄せて再確定した。正面から見ると「削った分」と「外殻の線」が釣り合い、公式の輪郭に戻る。
> 外部依存（応でしか決まらない値）は思へ戻さず**前提化**（幅の前提A〜C）。打切りは案の探索側でのみ作動（案1・2・A を棄却）。

## 十項（示式・順序固定）

### 1目的（応の指定）
公式 `/chikumo.svg` から実行時に起こした立体のこっこちゃんを、部屋（メタ空間）の台座に立たせ、回して眺め、つついて応えさせ、60秒の一日が暮れて眠るまでを見届けられる単一HTML（`/meta/index.html`）。実体化すれば成立。

### 2幅（制約と外部前提・破れの帰結を付す）
- **1ファイル自己完結**（HTML＋インラインJS＋素のWebGL1＋WebAudio）。外部3Dエンジン（Three.js 等）不使用（肥料学 巻二・mori2 の死因）。全シェーダの precision は頂点・断片とも `highp` に統一。
- **60秒で必ず終わる**（弐）。一日（朝→昼→夕→夜）を60秒で流し、夜でこっこが眠る。この60は畜学の幅であり廿式でない。
- 立体は**実行時に公式SVGから生成**する。立体の形をコードに手で書き込まない（品種を描き変えない）。
- 前提A：立体の見た目の係数（奥行き倍率・輪郭線の幅・削る幅）は応でしか決まらない。**破れ（膨らみすぎ／痩せすぎ／線が太い）→係数のみ調整（赦の経路）**。判定は許3の IoU と、正面・斜め・横・背面のスクリーンショット目視。
- 前提B：実機 iOS の WebGL の挙動はこの環境で確かめられない。`highp` 統一・`tryProg` 型の失敗時の降格・WebGL 不可なら公式SVGの2D表示で備える。**破れ→2D表示に退避（赦の経路）**。
- 前提C：背面用の「顔の部位を外した公式SVG」は `fetch('/chikumo.svg')` の文字列から作る。**破れ（fetch 失敗、または Blob の SVG で canvas が汚染される端末）→同一オリジンの `/chikumo.svg` で組み直し、背面も正面と同じ公式SVGで代用（赦の経路、顔が背面に鏡写しで出る劣化を許す）**。

### 3許（合格条件・判定可能な文・定め手＝作り手）
全必須（AND）。
1. タイトルに「さわってみる」があり、右下に🔄こっこ強制更新ボタンがある（部屋に入ると隠れる）。押すとキャッシュとService Workerを外してキャッシュバスター付きで開き直す。
2. 立体は実行時に公式SVGのアルファから生成される（シルエット→距離場→内接球の和→網）。形を表す座標の手書き定数が無い。
3. 正面（ヨー0・ピッチ0・遠方の狭角カメラ）で描いたこっこの輪郭（外殻の線込み）と、公式SVGのアルファの **IoU ≥ 0.95**（検証フックで実測）。
4. 横向き（ヨー90°・正射影）の丸みが正論蒔宿の参考画像に揃う：**横から見た奥行き÷背丈 ≥ 0.75**、**横から見た頭の奥行き÷正面の頭の幅 0.95〜1.1**、お腹は頭より細い（首にくびれが残る）。ヨー180°（背面）で目・くちばし・ほっぺが見えない（背面テクスチャに顔の部位が無い）。
   （第二周回の鳴で改定。初版は「横幅÷正面幅 ≥ 0.5」だったが、参考の絵を持たずに置いた閾値で、合格しても望みと違う形だった。示式 原則9）
5. ドラッグでヨーが回り、指を離すと慣性で減速して止まる。
6. つつくと、当たった点を中心に網がへこみ、ばねで弾んで戻る。部位（とさか・ほっぺ・くちばし・あし・背中・からだ）で音と反応が異なる。背中をつつくとこっこが振り返って正面を向く。
7. 二本の指が 250ms 以内にこっこへ同時に触れると「ぎゅっ」（左右から押しつぶれて弾む・💗が舞う・和音）が出る。マウス一本でも「ぎゅっ」に届く手段（ダブルクリック）がある。
8. 開始から60秒で空が朝→昼→夕→夜と移り、50秒前後であくびをし、60秒でこっこが眠る（頭を垂れてゆっくり揺れ、💤が浮かぶ）。音が止み、約3秒の静寂のあとに「おやすみ」の札と「あさにする（もういちど）」が出る。眠ったこっこはつついても起きない（終わりは終わり）。
9. WebGL が取れない端末では、公式SVGの2D表示（つつくと弾む）に落ちて動く。
10. ヘッドレス実ブラウザで起動→開始→つつく→ぎゅっ→60秒の終端まで通して `pageerror` がゼロ。変更したHTMLのインライン `<script>` が `node --check` を通る。

### 4範囲（扱う／扱わない）
- 扱う：立体こっこの生成と描画、部屋（空・床・台座・影）、回す・つつく・ぎゅっ、60秒の一日と眠り、WebAudio 合成音、2Dフォールバック、検証フック。
- 扱わない：同時に複数人が見える仕組み（正論蒔宿の選択＝まずはひとり。足すときは Firebase に新しいノードとルールが要る）／世界ランキング（ゲームでないため点を持たない）／保存（localStorage を使わない）／ズーム・ピンチ／目を閉じる等の**表情の描き足し**（眠りは姿勢と💤＝絵文字の重ねで表す。標準学 巻二）／敵（逆縁）を置くこと（相手を敵にしない六相は満たす。部屋に討つ相手は要らない）。

### 5構成（応に必要な要素）
- 画面：WebGL の canvas 一枚＋タイトル／おやすみの DOM オーバーレイ＋🔄ボタン＋絵文字の粒（DOM）。
- 状態機械：`title → room → sleep → end`。
- 生成系：公式SVG→オフスクリーン canvas→アルファのマスク→ユークリッド距離変換（Felzenszwalb の下側包絡）→線幅ぶん削る→内接球の和の高さ（同じ距離変換を `f=-d²` で回し、高さを決めた球の中心も記録する）→**大きさ連動の奥行き**（支配球の半径が大きい頭・胴は深く、とさか・うで・あしは浅いまま。頭頂の肩は持ち上げる）→マーチングスクエアで縁を滑らかに切った前後二面の網（縁の頂点を共有）→面積重み付き法線。
- 描画系：空（時刻で色が移る）／格子の床（距離で霞む）／台座／丸い影／外殻（裏面を法線方向へ押し出した黒）／こっこ本体（正面・背面テクスチャを局所 z の符号で切替、柔らかい二段の陰影）。
- 反応系：つつきの凹み（最大4点、各点にばね）／全身の伸び縮み（ばね）／ヨー・ピッチ（慣性）／跳ね／振り返り／ほっぺの赤らみ／眠り。
- 音：環境の和音（朝〜夕で移る）／部位ごとの声（ぴっ・ぽっ・こけっ・ぽよん・ぴ？）／ぎゅっの和音／あくび／終わりの静寂。

### 6工程（応の工程・各に入力/操作/出力/判定）
1. 雛形：音の番人ヘッダ・meta・style・canvas・タイトル／おやすみ DOM・🔄ボタン（`gp/` の reloadBtn を雛形）。判定：`node --check` 通過。
2. 生成系：公式SVGから網を作り、正面・背面テクスチャを焼く。判定：網の三角形数 > 0、縁が閉じている（前後二面が縁頂点を共有）。
3. 描画系：部屋とこっこを描く。判定：許3（IoU）と許4（横の厚み・背面に顔なし）をフックで実測。
4. **手触りゲート（10秒テスト）**：回す・つつくだけを先に実装し、つつきの凹みと弾みが指に同フレームで応えるかを、ここで止まって確かめる。応えなければ一日・眠りへ進まない（肥料学 巻二・二十五章 教訓（二）の「面白さを公開前に確かめる工程」をこの木に置く）。判定：許5・許6。
5. ぎゅっ・部位反応・音。判定：許6・許7。
6. 60秒の一日と眠り・静寂・おやすみ。判定：許8。
7. 2Dフォールバック。判定：許9（WebGL を切った起動で確認）。
8. 検（下記五条）→ ヘッドレス通し検証。判定：許10。

### 7担い（実行者と判定の担い手）
- 実行者＝作り手（AI）。判定の担い手＝作り手が許1〜10に対して合否を判定し、公開（main へのマージ）の可否は正論蒔宿が判定する。許は判定可能文のため交換可能。

### 8適応（実行者別の補正・核から分離）

### 9差分（記録先と形式）
- 立体化の手順（距離場→内接球の和→マーチングスクエア→外殻の線）は `docs/技術学.md`・`gijutugaku/index.html` へ（他の3D作が継げるレシピとして）。
- 迷い・二分した所は `docs/思考学.md`・`shikogaku/index.html` 巻二へ。
- 鳴分岐・示式を回した記録は `docs/鳴分岐.md`・`docs/示式.md` の事例へ。
- 次周回が無い単発差分は本書末尾の事例庫へ。

### 10継（次周回への遷移・昇格条件）

## 事例庫（単発差分・他設計書の思の素材）
- **第二周回（2026-10-17）：横向きの丸み**。公開前の確認で正論蒔宿が参考画像（丸い白いキャラの横向き）を示し「横向きは、これくらい丸みが欲しい」。初版は横から見ると細いレモン型（奥行き÷背丈 0.56・頭の奥行き÷正面の頭の幅 0.71）。三方式（A 一様な奥行き倍率／B 大きさ連動の奥行き／C 旋盤ブレンド）を別々に試作し、二名が参考画像の切り抜きと横シルエットを重ねて審査した。両名とも A（DEPTH 0.8→1.15）を勝者とした（参考との重なり IoU 0.958。B・C は胴が太り大福・カプセル形）。審査で A に「とさか・うで・あしは浅く（0.8）、頭頂の肩だけ持ち上げる（(h/R)^-0.35、上限1.5）」を足した形が参考との行ごとの幅の誤差を半分（0.041→0.0195）にしたので、これを採った。結果：奥行き÷背丈 0.79、頭の比 0.99、正面IoU 0.994 のまま、背面の顔 0。
- **目安の数字を参考の絵から測らずに置いた失敗**：試作に渡した目安「横シルエットの埋まり具合 fill ≥ 0.72」は、参考画像そのものの fill（約0.66〜0.69）より高かった。数字を満たしにいった B・C は胴を四角く太らせ、かえって参考から遠ざかった。審査は数字でなく参考シルエットとの重なりで判定して正しく戻った。**形の目安は、参考の絵から同じ物差しで測ってから置く。**
- **残る小さな破綻（正直に）**：ななめ上から見ると頭の左上に細い黒い線が1〜2本出る。外殻（輪郭線）が本体を突き抜けたもので（外殻を消すと消える）、初版にも薄く出ていた。奥行きが増えて少し目立つ。UVの寄せ幅の拡大・傾き連動の奥行きずらし（polygonOffset）の二手を試したが消えず、上限（二手）で打ち切った。次周回の素材とする。
- **第三周回（2026-10-17）：黒い線を消す**。公開後、正論蒔宿が iPhone の実機スクリーンショットで「黒い線けしてよ」。横〜後ろから見ると体の上に黒い横線が何本も出ていた（ヘッドレスでは「薄い1〜2本」に見えていたもの）。原因：縁の急な壁を4px格子で取るため、行ごとに縁からの距離がばらつき、頂点の高さと三角形から出す法線が段々に揺れる。法線方向へ押し出す外殻がその段で本体を突き抜けていた（外殻を赤く塗ると、旧版でも継ぎ目に沿って赤い横線が並ぶ）。
  - 試して捨てた手：①縁近くの頂点を縁から等距離の輪へ動かす（三角形が66枚裏返り、黒点が出た）②頂点は動かさず高さだけ輪で引く（腹の下に新しい線）③ステンシルで外殻を体の外だけに限る（体の上の線は全部消えたが、**腕の「U」など、手前の部位のふちの線まで消えた**。正論蒔宿「ふちのせんはけさないでよ！！ 余分な横の黒の線をけして ほかはけすな」）④部位（細い／太い）ごとのステンシル（腕の付け根が太い側に入り「U」が消えた）⑤体の上の外殻は体より線の太さ×2〜4倍手前のものだけ（「U」の付け根が欠け、横線も少し残った）。
  - 採った手：(a) **外殻を押し出す向きを、頂点の実際の位置での真の法線**（なめらかな奥行きの場 hz の勾配。縁の頂点は sdf の勾配で真横）にした。外殻が体の面から線の太さだけ離れた面になり、なめらかな所では体を突き抜けない（外殻の折れ 114→30）。(b) **自分の突き抜けだけを断片で間引く**：先に画面と同じ大きさの下書きへ「その画素に見えている体の点（変形前のモデル座標）」を記録し、外殻の断片は、押し出した元の点が下書きの点から線の太さ×2以内なら描かない。余分な横線は自分のすぐそば（2倍以内）から出ており、腕の「U」・外周・あし・とさかの線は自分から離れた所（3〜4倍以上）に描かれるので、ふちの線は全部残る。(c) 陰影は別の属性 aSN（縁近くは等距離の輪の上で引く）で横じわを消した。
