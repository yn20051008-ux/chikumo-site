# 要件定義 ─ メタ空間・第四周回「おもちゃの部屋」（トイストーリー級の部屋）

畜学カーネル（廿式）に従属する一本の木（`/meta/`）の大改修の設計書。作成手順は示式、思→鳴の分岐は鳴分岐に従う。
本体の設計書は `docs/要件定義-メタ空間.md`。本書はその「部屋（環境）」だけを作り替える周回の設計書で、こっこ本体（品種）の仕様は本体の設計書のまま変えない。

## 0 依頼と、決まったこと

- 依頼（正論蒔宿の言葉のまま）：「トイストーリーレベルの3D空間つくれる？ 君が1番得意な空間でいいよ」
- 空間の題材は作り手に任された。選んだもの：**こっこの目の高さから見た、子ども部屋の床**（木の床・ラグ・積み木・ボール・窓から差す日の光）。こっこはおもちゃとして部屋に立つ。
- 選んだ理由（作り手がいちばん得意な空間）：HTML1枚・素のWebGL1で映画に近い光（回り込む光・接地影・被写界深度）が出せるのは、**小さく閉じた室内**を式（距離関数）で描き、光線を辿って描くときだけ。広い屋外は形の量で負ける（シン島ぐらしの死因＝総量の勝負）。
- 先に引いた不可能の線（思考学 巻二・さらに 一の型）：ピクサーの1コマ数時間の計算・何百万の形・毛並み・映画級のモーションブラーは作らない。**トイストーリーらしさを作っている芯**＝①窓から差し込む柔らかい日の光と光の筋に舞うほこり ②おもちゃの接地影とすき間の陰り ③プラスチックや塗った木のつや ④おもちゃの目の高さで奥がぼける（ミニチュア感） ⑤映画の色、だけを作る。

## 鳴分岐（工程0思→1鳴で判定・ラベルにしない）

**① 成立判定（実行者によらず判定可能な一文）**
> 「`/meta/` を開くと、こっこが子ども部屋の床（木の床・ラグ・積み木・ボール）に立ち、窓の形の日だまりが床に落ち、こっこと積み木の足もとに柔らかい接地影があり、奥の物がぼけてこっこにピントが合い、光の筋にほこりが舞い、60秒の一日で日だまりの位置と光の色が朝→昼→夕→夜（夜はスタンドの暖かい灯りと月の青）と移ってこっこが眠る。こっこの品種（正面IoU・背面の顔なし）と全反応は従来どおり合格し、重い端末では自動で解像度を落とし、それでも重ければ今の部屋へ戻って動く単一HTMLが、pageerror ゼロで動く」──これが言えたら成立。

**② 反復の上限（幅の内に記す）**
> 方式は**最大3案・当日中**。見た目の撮り直しは**最大12回**で打ち切り、その時点で一番良いものを出す。
> - 案A＝部屋を距離関数で書き、光線行進（レイマーチ）で描き、毎フレーム1標本ずつの光（日の光の柔らかい影・1回の照り返し・すき間の陰り）を時間で積み重ねる。カメラは止まっている（こっこが回る）ので積み重ねが効く。
> - 案B＝部屋を三角形の網で作り、読み込み時に光を焼き込む → 家具ごとに網と UV を作る手間と、焼き込みの重い計算で棄却。
> - 案C＝今の格子の床と台座を飾る → ①〜⑤の芯（回り込む光・接地影・ぼけ）に届かないので棄却。
> - 採用：案A。

**③ 通った経路（差分として残す）**
> 経路＝**成立**（案Aで成立判定文が書けた）。外部依存（応でしか決まらない値）は思へ戻さず**前提化**：
> - 前提A：iPhone 実機の描画速度はこの環境で測れない → 1フレームの時間を測って内部解像度を段階的に下げ、下限でも重ければ今の部屋へ退避する仕組みで前提化（破れ→今の部屋＝赦の経路）。
> - 前提B：半精度浮動小数点の描画先（`OES_texture_half_float`＋`OES_texture_half_float_linear` があり、半精度の描画先が FRAMEBUFFER_COMPLETE になる端末。`EXT_color_buffer_half_float` は有効化するだけ）が無い端末 → 8ビットの描画先で積み重ねを浅く（破れ→ノイズが少し増えるだけ＝赦の経路）。※実装の初版は浅くしておらず、8ビットの丸めで絵が止まった（事例庫）。
> - 前提C：見た目の係数（光の強さ・色・ぼけの量）は応でしか決まらない → 撮り直し12回の内で調整。

## 十項（示式・順序固定）

### 1目的（応の指定）
`/meta/` の部屋を、こっこの目の高さから見た「おもちゃの子ども部屋」に作り替える。トイストーリーらしさの芯①〜⑤が一画面に同時に写り、60秒の一日で光が移る。

### 2幅（制約と外部前提）
- 1ファイル・素のWebGL1・外部ライブラリなし・全シェーダ `highp`。新しい外部ファイル（画像・音）を足さない。積み木の絵柄は**絵文字を canvas で焼いて使う**（標準学：独自アセットの前に絵文字）。
- こっこの品種は変えない：こっこの形・テクスチャ・輪郭線の経路はそのまま。部屋に合わせて変えるのは、こっこを照らす光の向きと色だけ。
- カメラは今のまま（こっこが回る）。部屋の物でこっこを隠さない。
- 前提A〜C は鳴分岐の③のとおり。

### 3許（合格条件・判定可能な文・定め手＝作り手、公開の可否＝正論蒔宿）
全必須（AND）。
1. 起動すると部屋は「おもちゃの部屋」で描かれる（検証フック `room()` が `toy` を返す）。WebGL が取れない端末は従来どおり2D表示。
2. 一画面に同時に写る（スクリーンショットで判定）：窓の形の日だまりが床に落ちる／こっこと積み木の足もとに接地影／奥の物がぼけ、こっこにピントが合う／光の筋とほこり／木目の床とラグ。
3. 朝・昼・夕・夜の4時刻で、日だまりの位置と光の色が変わる（4枚で判定）。夜はスタンドの暖色光と月の青で照らされ、こっこが眠る。
4. こっこの照明が部屋と揃う：日だまりに入った所が明るく、夕方は橙、夜は暗く青い。
5. 遅いフレームを模すと内部解像度が段階的に下がり、下限でも遅ければ今の部屋（格子の床・台座）に戻る（検証フックで判定）。
6. 回帰なし：正面IoU ≥ 0.95・背面の顔0・部位6種・背中の振り返り・二本指のぎゅっ・ダブルクリック・60秒で眠り→おやすみ→あさにする・2D表示・canvas汚染時の再試行がすべて合格。pageerror 0。`node --check` 通過。

### 4範囲（扱う／扱わない）
- 扱う：部屋の距離関数（床・ラグ・壁・幅木・積み木・ボール・こま・奥の家具）、日の光（窓の形）・空の光・照り返し・接地影・すき間の陰り・光の筋とほこり・被写界深度・映画の色（トーンマップ・ビネット・粒子）、時間の積み重ね、解像度の自動調整と退避、こっこの照明の部屋合わせ。
- 扱わない：こっこの形や表情の変更／カメラを動かすこと／トイストーリーの登場物や意匠（壁の雲柄など）の写し（壱：既視の禁。真似るのは光の文法で、皮ではない）／音の変更。

### 5構成（応に必要な要素）
- 部屋の描画（低い内部解像度）：一次光線 → 当たった物の材質 → 日の光（窓の四角を通るか＋柔らかい影の光線）＋空の光（すき間の陰り）＋1回の照り返し（ランダムな方向の光線）＋光の筋（視線上の数点で窓の光を受けるか）→ 前のフレームと混ぜて積み重ねる（ピンポンの2枚）。アルファに奥行きを入れる。
- こっこの影：こっこを近似する楕円体（形の資料 K の幅・高さ・奥行きから作る＝手書き座標でない）を、回転・跳ねに合わせて距離関数に入れる。
- 仕上げは二段：一段目（部屋と同じ低い内部解像度・8ビットの描画先）で蛍の抑え→奥行きでぼけ（被写界深度）→トーンマップ（ACES）・彩度・S字、二段目（画面の大きさ）で拡大・ビネット・粒子だけ（初版は全部を画面の大きさで回していた。事例庫）。
- こっこ（ラスタ）：今のまま描き、光の向き・色・空の色を部屋と揃え、日だまりに入っているかも窓の四角で判定する。
- 時間：一日の4時刻の光（太陽の向き・色、空の色、スタンドの灯り）を補間。
- 自動調整：2秒ごとの平均フレーム時間で内部解像度の段を下げ（画素数に比例する見積り）、下げても速くならず24fps以上出ていれば上限（30fps）とみなして戻して止め、下限（5万画素）でも24fpsに届かなければ退避。0.5秒を超えるフレームは一つなら数えず、3つ続けば数える（初版は移動平均で 0.75→0.6→0.5→退避。事例庫）。

### 6工程（応の工程）
1. 部屋の距離関数と一次光線だけで形を確かめる（撮り直し）。判定：家具がこっこを隠さず、構図に収まる。
2. 日の光（窓の形）と接地影・すき間の陰り。判定：許2の日だまりと接地影。
3. 照り返しと時間の積み重ね。判定：止まった画のノイズが消える。
4. 光の筋とほこり、被写界深度、トーンマップ。判定：許2の残り。
5. 一日の4時刻と夜のスタンド、こっこの照明合わせ。判定：許3・許4。
6. 自動調整と退避。判定：許5。
7. 回帰と検証（検の五条・審査）。判定：許6。

### 7担い
- 実行者＝作り手（AI）。判定の担い手＝作り手が許1〜6を判定し、トイストーリーらしいかどうか（見た目の良し悪し）と公開の可否は正論蒔宿が判定する。

### 8適応
- 検証環境（ヘッドレス Chromium・SwiftShader）は GPU が遅く、時間の積み重ねの収束も遅い。検証フックで時間を止めて標本を足す（`step` と `settle`）。この性質は核に入れない。

### 9差分
- 部屋の描き方（距離関数の部屋・窓の形の光・時間の積み重ね・こっことの合成）は `docs/技術学.md`・`gijutugaku/index.html` へ。
- 判断の分かれ目は `docs/思考学.md`・`shikogaku/index.html` へ。本書末尾の事例庫にも残す。

### 10継
- 正論蒔宿の判定（トイストーリーらしいか）を次の認の素材にする。部屋の家具や時刻を足す周回はここから降りる。

## 事例庫
- **経路と反復の実績**：経路＝成立（案A）。見た目の撮り直しは上限12回をちょうど使い切った（12回目は二度目の審査の見た目の指摘を確かめる1枚）。ほかに原因を一つに絞る診断の描き比べ3組（撮り直しとは別に数えた。思考学 巻二・はじめて・十）。
- **許の実測（応の判定）**：許1＝`room()` が `toy`（WebGL が無い端末は従来の2D表示で合格）。許2＝窓の形の日だまり・こっこと積み木とこまの接地影・奥のぼけとこっこのピント・光の筋とほこりの粒・木目の床と編んだラグが一画面に写る（1280×760 と 390×844 の撮影）。許3＝朝（白い光・大きな日だまり）→昼→夕（金色・低い光）→たそがれ→夜（月の青い日だまり＋奥のねむりの灯りの暖色）の4時刻で、日だまりの位置と色が変わる。許4＝こっこは日だまりに入った所だけ明るく、夕方は橙、夜は暗く青い。許5＝画面の大きさ3つ（390×844・1280×760・1920×1080）×模した端末7つ（60fps／30fpsの上限／中くらい／固定40ms＋部屋15ms／とても重い／約1fps／一瞬の長いフレーム）の21通りで、60fpsは下がらない・30fpsの上限は一度だけ試して元に戻して止まる・中くらいは一段で落ち着く・重い3つは7〜10秒で今までの部屋へ戻り資源を解放・一瞬の長いフレームは数えない。窓の大きさを往復（段0.45で 1280→640→2560→1280）しても元の画素数（320×190）に戻る。許6＝正面IoU 0.992・背面の顔0・部位6種・振り返り・ドラッグの慣性・二本指のぎゅっ・ダブルクリック・60秒で眠り→おやすみ→あさにする・2D・canvas汚染時の再試行、pageerror 0、`node --check` 通過（すべて見張りを止めたおもちゃの部屋で）。
- **作る途中で出た破綻と直し方**：こまの円すいの上を閉じ忘れて天井までの柱／壁の同心の輪（影の歩幅の縞→開始位置を毎フレームずらす）／ラグのモアレ（編み目を目からの距離でなじませる）／1画素の蛍（照り返しの頭打ち＋周り4画素の最大で抑える）／接地影が真っ黒（陰りの床を残す）／ラグの上の光った細い弧（柔らかい影の歩幅の取りこぼし→Aaltonen の改良版。機能を一つずつ外した描き比べで特定）。
- **審査で見つかった破れ（作り手の検証では見えなかった）**：①前提A：見張りが30fpsの上限（iOS の省電力モード・熱・PCの省エネ）を「遅い」と取り違え、**速いiPhoneほど10秒で今までの部屋へ落ちる**作りだった→「下げたら速くなったか」を見る形に直した ②前提B：8ビットの描画先で1/96・0.14の小さな更新が丸めで消え、**夕方の光のまま夜になって絵が止まる**→浅く積む・平方根で保存・確率的な丸め（半精度との差 3.5/255、直す前 17.1）③影の光線が窓の壁に近づくほど影を濃くし、**日だまりの明るさが歩数の上限で決まっていた**→遮れない床・壁・天井を影から外し、日の光を13%・朝昼の露出を下げて見た目を合わせ直した ④**灯りの影の光線が灯り自身の球に当たり**、夜の灯りがほとんど部屋を照らしていなかった→灯りの影では灯りを外した ⑤仕上げ（ぼけ25回の読み）を画面の解像度で回していて、解像度を下げても軽くならない→低い解像度へ移した ⑥ほこりがこっこより先に描かれ、こっこの前を横切ると消えた→こっこの後に描いた ⑦こっこの影の楕円体の回転の符号が逆（いまは丸いので見えない）。
- **二度目の審査で見つかった破れ（一度目の直しが生んだもの）**：⑧30fpsの上限を見分ける判定が、**大きな画面では下限への一歩が小さい（画素が18%しか減らない）ために「速くならない」と読み、16fpsのまま止める**作りになっていた（スマホの大きさでしか確かめていなかった）→「戻す先の段が24fps以上出ていた時だけ上限とみなす」⑨0.5秒を超えるフレームを全部捨てていたので、**1fpsの端末は判定の窓が永遠に埋まらず退避しない**→一つなら捨て、3つ続けば数える。起動直後に数えない間をフレーム数でなく秒で数える ⑩窓の大きさを変えると学んだ段が書き換わった→学んだ段と効いている段を分けた ⑪8ビットで平方根のまま混ぜると、ばらつく所が暗く偏る（夜の暗部で−5%）→線形で混ぜてから平方根で保存（半精度と平均が一致） ⑫ぼけの半径が内部解像度の画素で決まっていて、遅い端末ほど背景が大きくぼけた→段に合わせた ⑬タイトルではこっこが回るので「休む」が働かなかった→影の楕円体はほぼ丸いので向きを数えない。見た目：⑭窓の手前のふちが夕方のこっこの頭のすぐ外にあり、**金色の光が床にだけ落ちてこっこに当たらなかった**→窓を1寄せた ⑮たそがれの日が低すぎて画面に直接の光が無かった→少し上げた ⑯タイトルの説明文がこっこの輪郭線に重なって読めない字があった・ヒントが明るいラグの上で薄い→文字に縁取り。
- **許5の補い（同じ周回の内で見つかった許の欠け）**：許5は「遅いフレームで下がり、下限で戻る」だけで、「速い端末を落とさない」を書いていなかった。審査で上の①が見つかったので、検証には「30fpsの上限では落ちない・一瞬の長いフレームでは落ちない・窓の大きさを往復しても戻る」と、**画面の大きさ3つで確かめる**ことを足した。次の周回の鳴で許5の文そのものに入れる（示式 原則9）。
- **残すもの（正直に）**：iPhone 実機の速さはこの環境で測れていない（前提Aのまま。見張りが受け止める）。光の筋は「よく見ると在る」強さに留めたので、小さな画面では気づきにくい。タイトルの文字はこれまでどおり部屋の上に重なる（配置は今回の範囲外。読めるよう縁取りだけ足した）。
